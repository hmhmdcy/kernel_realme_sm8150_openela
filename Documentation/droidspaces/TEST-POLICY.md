# 内核与容器的测试范围

2026-10-05 根据用户复盘要求，日常采用“新功能专项验收 + 受影响功能短回归”。用例必须有明确行为和失败判据；源码、配置或文件存在只作前置核对。依据见[测试复盘](VALIDATION-REVIEW.md)。

每批一次构建/配置/模块 ABI/打包核对、一次启动身份核对、负载前后各一次必要宿主健康核对及一次清理核对。保留镜像、boot ID、测试源码摘要、SELinux Enforcing、普通 guest 过滤与失败日志。探针始末核对身份，期间不反复枚举设备或回读整个 boot。ABI 变化审查实际外部模块及相关驱动，不自动扩展为整机硬件认证。

| 改动 | 必做验收 | 扩大回归的条件 |
| --- | --- | --- |
| 文档、报告展示 | 链接/格式或离线输出 | 不刷入、不重启、不跑手机压力测试 |
| 容器工具、OCI hook、策略服务 | 真实创建/exec、目标绑定、资源生效与清理 | 改持久化才完整生命周期；改 UID/运行时布局才扩展对应模式 |
| PSI、memory.high、内存回收 | 有界压力、some/full 独立通知、父组/邻组；改移组统计时测负载中移组 | 短 quota/过滤/LMKD 回归；涉及 CPU 权重、统计或 cpuset 才完整调度矩阵 |
| CPU/cpuset/WALT | 真实 quota、权重、affinity、fork/exec 和相关层级 | 改热插拔才离线 CPU；改宿主调度兼容才应用前后台/Power HAL |
| Binder | 真实 Android 16 公开 API/回调及相关生命周期 | 改 Binder/冻结才完整专项；不顺带跨架构、网络吞吐 |
| seccomp/binfmt | 对应真实 syscall/代理或跨架构运行及权限/清理边界 | 改对应公共路径才上游完整集/跨架构构建 |
| eBPF/网络/IO | 当前 ROM/容器实际接口与有界负载，记账或允许拒绝效果 | 改吞吐算法才测吞吐；续航、长稳按明确需求单独安排 |
| 通用 cgroup、初始化、guest/ROM/运行时整体升级 | 受影响控制器、委派/systemd、生命周期及联合验收 | 可全套；注明扩大范围原因 |

新功能首次交付保留 rootful/rootless 权限边界；默认 crun 完整功能与生命周期，runc 核心功能/启动/exec 兼容。运行时专有修改、差异或失败时扩展对应矩阵。共用内核的参数/触发器关闭循环等边界验证一次；权限或布局相关边界分别验证。some/full 各自证明订阅生效，完整停止启动/重建/guest 重启只做一套；修复订阅语义时按影响补测。

新镜像仍需实际验收本次功能；旧 boot 结果只作继承基线。同 boot 且镜像、工具/依赖、测试源码、夹具状态均适用的已完成结果可引用报告及摘要，不为汇总再跑。持久化只做一次真实 guest 重启，不以手机重启代替。

刷入前完成补丁审查、编译/链接、实际配置/ABI、boot header/DTB/ramdisk/容量及可离线执行的夹具和接口 ABI 检查。可兼容、可定位的功能合并成一批，目标一批一次刷入；实测内核故障允许修复并再刷。脚本、日志、等待或判据修正复用现有镜像，不重刷相同镜像。复用已有授权和固定序列号，不重复 adb/fastboot 枚举或 getvar。guest 可用时直接复用，不为每个用例重装工具或重配控制器。

失败先区分内核、用户态兼容、夹具和 USB 问题，读原任务状态及相关字段后继续收集；不盲目重放启动/刷写。错误判据可依据实际语义修正并保留前后证据，真实失败不能删用例或降门槛宣布通过。通过后停止该项；无新改动、失败或具体疑问不扩大测试。

完整 JSON/日志留文件，终端只输出状态、必要指标、失败摘要和证据路径；按字段查看，不整份回灌大日志、CRC 差异或历史源码。device_runtime.py 仅 --verbose 打印完整报告。来源和证据摘要用脚本核对，避免人工重复阅读/复制/封存。完整构建目录保留最新已验收及当前候选，旧失败保留补丁、配置、摘要和相关日志，按明确的空间保留清单清理。

Wi-Fi 开关/重连、热点与频段、传感器、显示/触摸、指纹、相机、音频、蓝牙、NFC、GNSS、SIM/IMS、USB/OTG、快充及整机硬件认证均已从默认测试要求中移除。未逐项认证的硬件不列为本项目的未完成验收或后续待办。

仅在用户明确要求、出现相关故障，或改动直接涉及该硬件的驱动、设备树、HAL、配置或模块 ABI 时，按需验证受影响的功能。容器 DNS/NAT/WireGuard 等网络功能仍按实际改动验证，不因此自动安排 Wi-Fi 开关测试。模块 ABI 和驱动兼容性审查仍保留。

accept_phone.py 是准备 guest 并运行累计测试的旧全套入口，只在显式 `python scripts/accept_phone.py --full` 时使用，不作为专项默认入口或替代新功能验收。Wi-Fi 专项须另加 --with-wifi，汇总时 record_extension_acceptance.py 同样须明确选择。

默认不重复真实 panic，不做无关 BBR 电流/吞吐对照，不恢复暂停的完整 Android 16 桌面，不将 EL2 不可用的 KVM/AVF 纳入近期验收。历史结果和失败原样保留，历史全套要求不覆盖本政策。未执行项目记作未执行或继承，不记作当前通过。
