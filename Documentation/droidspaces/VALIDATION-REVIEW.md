# 2026-10-05 测试复盘

用户要求减少刷入与 token 消耗，集中功能验收和迭代。依据原始报告及脚本，有价值的故障用例保留，削减矩阵重复、全套默认入口和大量日志展示。执行要求见[测试范围](TEST-POLICY.md)。

| --- | --- | --- |

| Android 16 Binder 公开回调 | 发现 h5bf 能力发现缺失，原生 ioctl 不足以替代应用 API | 保留首次交付及相关回归；刷入前核对 ABI/能力发现前提 |
| PSI full-only 通知 | a16ps 有计数却无通知，发现真实内核回收状态问题 | 独立 full 通知保留，配置/计数不能代替 |
| some/full 各四种模式并各做完整停止启动/重建，另做四种 guest 重启 | 核心订阅需要分别证明，但相同策略生命周期被重复覆盖 | 订阅各测；完整生命周期一套，crun 完整、runc 核心兼容，权限/布局边界保留 |

| 完整 JSON/数千 CRC 差异进入终端，人工重复阅读封存 | 证据需保存，反复进上下文没有功能收益 | 全量留文件、默认短摘要，脚本按字段/摘要核对 |
| 无关 Wi-Fi/传感器、BBR 电流、panic、CPU 热插拔 | 部分历史专项有授权，不适合每轮回归 | 移出默认；相关改动或明确要求时才做 |

扩展阶段有 11 份确认写入 boot 的部署记录，部分是真实功能失败后的修复，不能断言某次刷入完全多余。减少的是“每个小阶段刷一次”：预先审查用户态前提，合并兼容补丁，工具/夹具修正复用当前镜像。真实内核故障仍须修复后实测。

复盘时 runtime 有 1,446 份 JSON；本轮 CPU 报告为 236,773 字节，完整打印不是必要步骤。报告数或用例数不等于完成度；以后汇报新增行为、关键指标、失败原因/修复及证据路径。这些是本地记录数量，不是节省比例承诺。

刚结束的 a16pf 已完成同 boot 的 some/full、回收移组、目标绑定、真实 guest 重启持久化及受影响回归，生成联合验收（本地 group-psi-acceptance.json）。本次未为复盘追加刷入、重启或压力测试，历史失败/验收记录未改写。

下一步 eBPF 在已验收 a16pf 上核查当前 ROM 实际使用的 CPU/timeInState 和网络记账/接口，有界负载可用即可结束。具体消费者出现缺失/错误才迭代内核，不因版本号或理论接口清单扩大回移。完整 Android 16 桌面继续暂停。
